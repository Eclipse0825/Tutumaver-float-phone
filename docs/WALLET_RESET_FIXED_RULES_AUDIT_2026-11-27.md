## 已实现

### 钱包重置

钱包设置的“完成”下方新增“重置余额与流水”，确认框明确当前所选账户。只重置选中的 user 身份或 char，不需要查手机。捕获具体账户 ID 后再请求模型，切换账户不会把结果写给另一个人。

先在内存生成新基础金额和生活流水，全部成功且原账户/人设未变化才一次替换。失败、格式错误或并发新交易不覆盖旧钱包。余额、多币种余额、可见流水、旧信用卡欠款、旧生成进度及固定规则执行记录重建；银行卡和当前财务配置、可选规则保留。贷款规则按当前填写的初始本金建立新账本余额。

新账本有独立 epoch 和 resetAt。初始化只使用当前人设、经济情况及收入来源，不读取其他 APP 残留。后续只允许重置后创建的聊天/日程参与生活流水。旧已处理账务只留下不含标题、描述及旧余额的防重复凭证；旧单聊/群聊消息引用、可识别的旧订单引用不能重新记账。旧生成请求及旧快照不能覆盖新 epoch。

完整版的旧 YouTube 未提现收益，以及重置前开播但重置后才结算的旧直播，不自动入新钱包；平台历史及提现状态不被伪造。新收益仍正常且只入账一次。分享版不引入用户端 YouTube 或提现互联。

### user 初次生成

user 首次刷新资产时，只有系统默认一万元初始占位记录的账户会按当前用户人设重新建议基础资产；不会重复给已有真实余额/流水的钱包重新初始化。char 也走同一套生成与并发保护。用户上下文按当前绑定身份筛选，避免混入其他 user 身份的会话。无固定规则时保留自然生活收支生成。

### 固定收支（选填）

位置在经济情况、收入来源下方；支持添加、编辑、停用和删除，字段包括名称、类型、金额、币种、每月日期或月底、开始/结束月份。支持固定收入、支出、信用卡还款和单独借款还款。借款需填写初始本金及每月本金，其余为本期利息；还清停止扣款，不把全部月供当作本金。

仅打开/切换所选钱包或现有刷新操作时检查到期项目；不增加定时器、后台闹钟或 API 请求。漏开的自然月按规则补记并保存月份标记，同一规则同月只成功执行一次。短月自动使用月底；余额不足为待处理，后续操作重试，不伪造扣款或偿债。债务尚有本金时，删除操作改为停用并提示，避免误删负债。

固定项目由程序记账，并在 AI 提示词及结果筛选中排除相同来源/常见固定描述，减少工资/信托/还款重复生成。规则本身不依赖模型判断。重置后只从新账本的重置当月补记，不追补旧 AU 月份。

### UI

两版新增组件/样式一致，使用现有钱包配色、日夜变量、字体缩放、圆角和紧凑按钮。角色配置页只展示可配置规则，不展示实际余额或实际欠款。

可见普通原生 checkbox 统一沿用现有 16px 圆形、黑色选中样式；保留键盘焦点、禁用态和原有多选行为。开关、隐藏代理输入、sr-only/peer/opacity-0 等不被改成普通勾选框。没有改动标签字号或把复选框变为单选。

## 边界与未验证

- 未调用真实模型/付费 API，也没有手机或真实浏览器的视觉验收；DOM 事件和样式选择器检查不能代替实机字号、夜间、滚动与点击区域确认。
- 固定规则结算为程序逻辑、额外 API 次数为零；首次资产生成/钱包重置仍需正常的模型请求。基础金额建议及生活流水各走一次生成，不是靠固定规则额外触发。
- AI 自由生活流水仍是模型生成；程序禁止固定来源复刻并做结果过滤，不宣称能理解所有任意同义描述。
- 钱包重置不会删除聊天、日程、订单或平台历史本体；它们与新钱包按财务期隔离。未知第三方 APP 如未提供可识别交易引用、来源时间或财务期，不能只凭钱包猜出任意外部事件属于哪个 AU。
- 固定规则按设备本地自然月/日期结算，单次最多回溯 1200 个月，避免异常配置无限循环。
